# Project Brief and History

**Project:** Daniel Shabrokh Podcast Website (independent proposal)
**Repository:** https://github.com/Maverick-Limitless/Daniel-Shabrokh-Podcast-Website
**Last updated:** 2026-10-19 (verified against `git log` and the working tree)

## Objectives

Build a polished, editorial-style website that presents the Daniel Shabrokh
podcast as a credible independent proposal: one coherent destination for
video, audio, and written insights, with a private single-administrator CMS
so real content can be managed without touching code. The product must be
presentable to the podcast owner as a serious proposal that could be
licensed or developed further.

## Audience

- **Primary:** the podcast owner (evaluation of the proposal) and,
  eventually, site visitors browsing podcast content.
- **Secondary:** the site administrator (content management) and any
  developer inheriting the codebase.

## Non-goals (deliberately out of scope)

Public user registration, multi-role permissions, comments/social
features, payments, custom video hosting or transcoding, analytics, email
delivery, and presenting the site as official or endorsed without
documented owner authorization.

## Product principles

1. Never invent facts — no fabricated biography, credentials, quotes,
   episodes, dates, endorsements, or affiliations; unverifiable content
   is replaced by honest "pending verification" states.
2. Editorial craft — premium, restrained design (ink/navy, warm ivory,
   restrained gold), distinctive typography, deliberate composition — not
   a generic template.
3. Real behavior only — every visible control works; drafts never leak to
   the public site, search, feeds, or sitemaps; no fake metrics or success
   messages.
4. Security and privacy by default — hashed sessions, strict CSP, no
   third-party tracking, privacy-enhanced YouTube embeds behind
   click-to-load.

## Current status

**Proven by repository/tests:** all features listed in the README work
end-to-end; 34 unit tests and 38 Playwright E2E tests pass against a fresh
production build (2026-10-19); `pnpm audit` is clean; svelte-check is
clean; Core Web Vitals are lab-measured (see README caveats); genuine
production-build screenshots are archived in `docs/screenshots/` and
regenerated by `pnpm test:e2e`.

**Goals (not yet facts):** owner-authorized publication; an independent
visual review of the archived screenshots; field performance data; real
content.

**Open owner decisions:** publication authorization and the site's official
status; verified biography, portrait, official links, and contact
channels; real episode/audio sources and rights; the `og:image` brand
asset; the production domain/hosting target.

## Release gates

1. **Content & authorization** — owner-approved content and explicit
   permission to present/publish the site.
2. **Independent visual review** — a review pass over the archived
   screenshots.
3. **Deployment destination** — no host or domain exists yet.
4. **Field performance data** — lab metrics exist; real-user data does not.
